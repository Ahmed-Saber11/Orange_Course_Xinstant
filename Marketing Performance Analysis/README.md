## 🎯 Problem Statement

> *"We want to understand, overall, how marketing is performing."*

That request from the marketing team is the starting point for this project. Campaign, subscription, flash-sale, bundle, and post-refund satisfaction data lived in one raw file with no shared, trustworthy structure, no agreed KPI definitions, and enough data-quality issues that simple totals couldn't be trusted. This project delivers a clean data model, a defined KPI framework, and two executive dashboards that give the team **one overall, on-demand view** of marketing and product performance — replacing five disconnected spreadsheets with five different answers.

## 🗂 Project Overview

This is an end-to-end analytics project covering:

1. **Business understanding** — defining the problem, scope, and KPIs before touching any code
2. **Data cleaning** — diagnosing and fixing nine categories of data-quality issues, each backed by evidence, not assumption
3. **Feature engineering** — 12 business-ready ratios and segments (ROI tiers, discount buckets, satisfaction segments, etc.)
4. **Data modeling** — normalizing the cleaned dataset into a Power BI star schema (1 fact table + 4 dimension tables)
5. **KPI design** — a 24-measure DAX library organized into 4 business-aligned categories
6. **Dashboarding** — two executive dashboard pages answering the business's most important questions, phrased as questions
7. **Recommendations** — five prioritized, evidence-based business recommendations

## 📁 Dataset

- **Grain:** one row per marketing campaign, with attached product, customer, flash-sale, bundle, and post-refund satisfaction attributes
- **Size:** ~10,080 raw records → 9,691 clean records after deduplication

| Column | Type | Business Meaning |
|---|---|---|
| `Campaign_ID` | ID | Unique identifier for a marketing campaign |
| `Product_ID` | ID | Unique identifier for the product being marketed |
| `Budget` | Numeric ($) | Marketing spend on the campaign |
| `Clicks` / `Conversions` | Numeric | Funnel activity generated by the campaign |
| `Revenue_Generated` | Numeric ($) | Revenue attributed to the campaign |
| `ROI` | Numeric (ratio) | Return on investment |
| `Customer_ID` | ID | Unique identifier for the customer |
| `Subscription_Tier` / `Subscription_Length` | Categorical / Numeric | Customer's plan and tenure |
| `Flash_Sale_ID` / `Discount_Level` | ID / Numeric (%) | Flash-sale event and discount depth |
| `Units_Sold` | Numeric | Units sold during the flash sale |
| `Bundle_ID` / `Bundle_Price` | ID / Numeric ($) | Product bundle and its price |
| `Customer_Satisfaction_Post_Refund` | Numeric (1–4) | Satisfaction captured after a refund |
| `Common_Keywords` | Categorical | Marketing keyword tag for the product |

## 🔍 Methodology

### 1. Data Cleaning & Quality Assurance

Every issue was diagnosed from the data itself, then fixed with a verifiable rule and re-checked:

| Issue | Approach |
|---|---|
| Fully duplicated rows & duplicated campaign-key records | Dropped, keeping one clean record per campaign |
| Inconsistent text (case, whitespace, typos in `Subscription_Tier`, `Common_Keywords`) | Standardized to a clean, consistent category set |
| Sign errors (negative `Budget`, `Units_Sold`) | Corrected via absolute value |
| Scale / decimal-point errors (6 columns ~100x too large) | Corrected via ÷100, sign preserved — verified against each column's normal range |
| Offset error (`Discount_Level` > 100) | Corrected via −100 |
| Out-of-scale satisfaction values | Excluded from scale-dependent analysis rather than guessed |
| Incorrect data types | Cast to proper categorical / integer types |
| Right-skewed distributions | Added log-transformed companion columns for skew-sensitive analysis |
| `Conversions` occasionally exceeding `Clicks` | Documented as a known tracking-integrity limitation, not silently patched |

### 2. Feature Engineering

12 engineered features translate cleaned columns into business-ready metrics, including `Conversion_Rate`, `Cost_per_Conversion`, `Revenue_per_Dollar_Spent`, `ROI_Tier`, `Discount_Bucket`, `Subscription_Tenure_Group`, `Satisfaction_Segment`, `Budget_Tier`, and `High_Value_Campaign`.

### 3. Data Modeling — Power BI Star Schema

The cleaned dataset was normalized into a star schema:

```
                     Dim_Product                    Dim_Customer
                  (Product_ID, Keywords)      (Customer_ID, Tier, Tenure)
                            \                          /
                             \                        /
                              Fact_Campaign_Performance
                              (grain: one row per campaign)
                              /                        \
                             /                          \
                  Dim_FlashSale                    Dim_Bundle
              (Flash_Sale_ID, Discount)        (Bundle_ID, Price)
```

Each dimension connects to the fact table via a single-direction, many-to-one relationship — the standard pattern that lets any dimension attribute filter every KPI.

### 4. KPI Framework

A dedicated **KPIs** measures table sits on top of the star schema with **24 DAX measures** across four categories:

| Category | Count | Examples |
|---|---|---|
| Marketing | 12 | Avg ROI, Cost per Conversion, % Profitable Campaigns |
| Flash Sales | 4 | Total Units Sold, Avg Discount Level, Revenue per Unit |
| Bundling | 1 | Avg Bundle Price |
| Customer / Volume | 7 | Avg Satisfaction Score, % Detractors, Distinct Customers |

### 5. Dashboards

**Dashboard 1 — "Is Our Marketing Spend Actually Paying Off?"**
Budget vs. revenue, ROI-tier mix, ROI tier by budget tier, cost per conversion by tier, worst-performing campaigns.

**Dashboard 2 — "Are Discounts, Bundles, and Subscriptions Actually Working for Customers?"**
Discount depth vs. units sold, discount depth vs. satisfaction, subscription tier value comparison, revenue by marketing keyword, post-refund satisfaction split.

## 💡 Key Findings

- **Budget size shows no relationship with revenue or ROI** — the smallest-budget campaigns perform as well as the largest.
- **88.8% of campaigns are profitable** (ROI ≥ 1); only 0.3% are outright loss-making, and the loss-making tail is traceable to a small, identifiable set of campaigns.
- **Neither discount depth nor bundle price nor subscription tier moves revenue, units sold, or satisfaction** in any meaningful way.
- **Marketing keyword performance is close across the board** — "Affordable" and "Innovative" lead only narrowly.
- **50.4% of post-refund customers are Detractors** (score 1–2 on a 4-point scale), regardless of tier, discount, or keyword — the single highest-leverage finding in the dataset.

## 🚀 Business Recommendations

| # | Priority | Recommendation |
|---|---|---|
| 1 | High | Move budget allocation to a test-and-learn framework; pause the bottom-ROI decile and reallocate to the top quartile |
| 2 | High | Run a controlled discount-depth experiment before defaulting to deep flash-sale discounts |
| 3 | Med-High | Audit the campaign-tracking pipeline (`Conversions` vs. `Clicks` mismatch) and add automated data-quality validation |
| 4 | Medium | Reassess Premium subscription pricing/packaging — it isn't outperforming Basic |
| 5 | Medium | Treat the post-refund moment as a service-recovery opportunity with closed-loop follow-up for low scorers |


## ⚠️ Limitations & Next Steps

- No date/timestamp column — trend and seasonality analysis isn't possible with the current data.
- All relationships reported are **correlational, not causal** — the flat relationships found are a real finding but should be validated with controlled experiments before major budget shifts.
- `Conversions` occasionally exceeding `Clicks` means marketing-efficiency ratios should be read as directional pending a tracking-pipeline fix.

**Recommended next data to collect:** event timestamps, a clean event-level click/conversion log, customer purchase history over time, and controlled discount-depth/budget experiments.
